Overview

memeval is a Go evaluator for personal-agent memory retrieval and answer quality on public benchmarks. It normalizes each benchmark into a common suite (episode → events → cases), uses a shared adapter protocol to drive systems, runs each external runtime episode in a container, and produces machine-verifiable reports.

Data Registry entry + upstream lock → memeval import → normalized suite bundle
Integration One manifest v3 + one adapter (Python / Node / HTTP / native Go)
Install env install builds a Linux SUT image, writes Lock v3, and runs selftest
Run One container per external runtime episode: reset → ingest → ready → retrieve → destroy
Results report.json / cases.jsonl / report.html, including isolation, data flow, and log indexes
Cleanup Residue check after each run; env destroy, gc (dry-run by default)

The evaluator runs on the host; external SUTs run in Linux containers; built-in baselines run in-process. Gold answers and dataset files are not mounted into SUT containers. Only visible events and queries cross the protocol. Network mode none restricts SUT runtime egress. Image builds, dependency/model downloads, and evaluator reader/judge calls have separate data flows that require their own configuration and disclosure.

Quick start

Requirements: Go 1.27, Python 3 standard library, and a Docker daemon. The code uses the standard docker CLI with explicit --context.

# 1. Build the evaluator and static Linux container probe
go build -o bin/memeval ./cmd/memeval
scripts/build_linux_memeval.sh arm64

# 2. Fetch official judge templates (verified by SHA-256 at runtime)
python3 -B scripts/fetch_upstream_refs.py

# 3. Configure MEMEVAL_DOCKER_CONTEXT and, if needed, MEMEVAL_SUT_LLM_*
cp .env.example .env

# 4. Check container capabilities (all five required checks must pass)
bin/memeval sandbox caps

# 5. Install a SUT (image, lock, selftest), then evaluate
bin/memeval env install suts/mem0/manifest.json
bin/memeval run --suite data/normalized/pmb-retrieval.json --sut suts/mem0/manifest.json --out reports/mem0-pmb

# 6. Review results and clean up
open reports/mem0-pmb/report.html
bin/memeval gc            # dry-run: list reclaimable memeval resources
bin/memeval env destroy mem0
Built-in baselines need no container: bin/memeval run --suite pmb --sut bm25 (also null, recent, fullcontext ). They run in-process and are reported as Tier C.

Dataset details

The following entries describe data, capabilities, sizes, variants, scoring, integration status, and limitations. Facts come from data/registry/<id>.json, protocols/<id>.json and import specifications. Registry states: run means a run is recorded, imported means normalization and a protocol are available, and registered means only the source is registered. Status does not imply all systems were tested, full coverage, or official fidelity. Consult each run's status, sample count, and fidelity/deviations.

Source

A structured synthetic diagnostic set: one user, 35 seed facts about technology, conventions, and preferences, and 77 questions. It specifies which facts should or should not be retrieved, rather than supplying conversations.

Normalized suite format

Two storage formats: Single file (schema 2.0, four early suites) and bundle directory (schema 3.0 for the others). Go types are in internal/suite/suite.go and v3_types.go, memeval suite schema can export JSON Schema; the specification is in design/dataset-protocol.md(v1.2).

data/normalized/<suite-id>@<rev12>/
├── suite.json             # Suite header + container{format:"bundle",version:"1",episodes_file,index_file,index_sha256,episodes,events,cases}
├── episodes.jsonl         # One episode per line: {id, cluster_id, events[], cases[]}
├── episodes.index.jsonl   # Per-episode index {id, cluster_id, line, offset, bytes, sha256, events, cases}
└── import.json            # Import statistics: converter, counts{by_kind,cases,episodes,events,unresolved_evidence_refs}, by_category, diagnostics

episode / event / case

  • episode: id, cluster_id (cluster unit for pairing and bootstrap; defaults to id), events[], cases[].
  • event: source_id (unique within episode, used as the retrieval evidence ID), owner, role (user / assistant / system / observation / fact; 3.0 adds tool), content, session, timestamp, time_raw, turn_group, modality, attachments[], attributes.
  • case: id, kind, query, user, scope[], category, cutoff (exclusive event-prefix index: the SUT sees only events[:cutoff]; gold evidence must precede it), budget{top_k,max_context_chars}, options, query_point, question_type, gold.
  • gold: answers[], abstain, evidence_ids[], evidence_session_ids[], evidence_unit(event | session), exhaustive, choice, expect (PMB typed assertions); 3.0 also adds evidence_refs[]{kind,ref}, mcq{seed,order,shuffle,parse}, rubric{items[{group,text,polarity,weight}],aggregate}, checker{type,params}, memory_points[], reference, disputed.

suite_sha256 for bundles is sha256(canonical suite.json + "\n" + raw episodes.index.jsonl bytes); single files use canonical JSON SHA-256. Reports use this identity to prove which dataset was evaluated.

Case kinds and scoring

Both 2.0 and 3.0 support typed_context, qa, mcq, retrieval; 3.0 also supports rubric, set_match, ordering, summary, memory_audit, recsys, agentic. 3.0 kinds run only when their benchmark predicates match; otherwise the case is unsupported and included in warnings.

memory-only(--mode retrieval, default)

The evaluator scores returned evidence IDs. References must exist, precede the cutoff, and not repeat.

  • typed_context (PMB): use gold.expect to validate pinnedFacts / relevantBeliefs / openQuestions / personaPrelude.
  • Other kinds score gold evidence using hit, recall, mrr, all_evidence, ndcg, precision, empty_result_correct @top-k; evidence units are events, or sessions when evidence_unit=session. LongMemEval additionally reports recall_any / recall_all / ndcg_any.

fixed_reader(--mode fixed_reader)

A fixed evaluator reader answers from retrieved material, then benchmark-specific official scoring is applied.

--reader-input sources (default) expands original events by source ID. LongMemEval, MemoryAgentBench, and BEAM also support explicit --reader-input items for SUT-returned memory text. Sourceless synthesized memories can answer in items mode, but retrieval metrics are unavailable for that case. Illegal references remain errors. Reports disclose input mode and deviations; these modes must not be pooled. fullcontext accepts sources only.

Benchmark protocol declarations protocols/<benchmark>.json

One file per benchmark declares variants, official scoring, template files and hashes, and equivalent deviations. Suites reference it through protocol_ref; memeval run uses benchmark.ResolveAt to load and verify it, then records protocol.benchmark{protocol_id,version,variant,ref,sha256}.

  • scoring.primary ∈ judge | exact_match | token_f1 | mcq | nugget | assertions | retrieval.
  • Template files ( design/upstream/… ) have individual licenses and are not committed. Missing files or hash mismatches make run fail with guidance to python3 -B scripts/fetch_upstream_refs.py --only <name>.
  • Available files: beam, convomem, halumem, locomo (version 2), longmemeval, memora, memoryagentbench, personamem, precisionmembench, prefeval.

Rebuilding and verifying data

  1. Official templates: python3 -B scripts/fetch_upstream_refs.py using design/upstream/<name>/sources.md commits and SHA-256 values; --verify-only verifies offline.
  2. Dataset contents: memeval fetch longmemeval-s --revision <locked revision> --ack-license is the only built-in downloader; fetch other datasets according to data/upstream/<name>/source.lock.json(dataset_id, source_url, revision, files[]{path,bytes,sha256} or files_manifest + files_total ) into the same directory.
  3. Import: memeval import <dataset> --input … --out data/normalized/<suite-id>@<rev12> (pmb / longmemeval / locomo / personamem / memoryagentbench / beam / memora / halumem / prefeval / convomem; see options in --help).
  4. Verify: memeval validate <suite> (structure, semantics, gold-leak scan); memeval registry check --verify-files recomputes file SHA-256 values and checks suite suite_sha256, import statistics, protocol references, and symmetric overlaps, producing {ok, entries, problems[], warnings[]}.

Data: the example case

The importer projects PMB into one episode with 35 role: fact seed facts (owner test-user, session seed ) and 75 cases. This case is: 

{
  "id": "alias-kube-resolves", "kind": "retrieval", "category": "Alias resolution",
  "query": "how does kube schedule pods across our CI pipeline nodes?",
  "user": "test-user", "cutoff": 35,
  "gold": {"evidence_ids": ["b-ci-gha-entity", "b-kubernetes-entity"], "evidence_unit": "event", "exhaustive": true}
}

The two gold events begin “Deploys services to a Kubernetes cluster on EKS…” and “CI/CD runs on GitHub Actions…”. The query only says kube and CI pipeline, testing alias resolution. exhaustive: true means gold is exhaustive, allowing precision calculation.

Runtime: only SUT-visible information enters the container

memeval run --suite data/normalized/pmb-retrieval.json --sut suts/mem0/manifest.json --run-seed b53400d4…. Preflight checks: suite suite_sha256 matches the registry; protocols/precisionmembench.json#retrieval resolves with the expected file SHA-256; the environment lock is valid and selftest passed within 24 hours. Each case then follows this exchange.

Each ingested PublicEvent contains only {id, owner, sequence, role, content, timestamp, session_id, attributes}; gold, cases, and dataset files remain on the host. Mem0 uses local fastembed to populate its vector store in the EP directory and retrieve by query. Network mode none blocks runtime external connections.

Scoring: source_id references

The case record in cases.jsonl contains: status: scored, retrieved_source_ids 10 items, metrics{hit:1, recall:1, mrr:0.5, ndcg:0.6934, precision:0.2, all_evidence:1}, timings{reset_ms:2399, ingest_ms:992, ready_ms:0.7, query_ms:32}, namespace: paeval_54558c1b…. All 75 cases aggregate into summary.metrics and by_category (Alias resolution: 23 cases).

Verification: six independently reviewable checks

  1. Dataset identity: report suite_sha256 = 64bdace8… matches the registry; memeval registry check --verify-files recomputes it.
  2. Protocol identity: protocol.benchmark{protocol_id: precisionmembench, variant: retrieval, sha256: e7819c69…}; judge benchmarks also verify official template SHA-256 values.
  3. Isolation: all 23 historical none-mode preflight selftests passed: no gold or host-path visibility, read-only rootfs, blocked external DNS/TCP/TLS. The report records isolation.tier=D, network_enforced=true.
  4. Valid references: each source_id must exist, precede cutoff, and not repeat; otherwise the case is invalid. All ten references in this case are valid.
  5. No residue: after each episode, enumeration by label=memeval.episode returns zero resources. At run end: residue{containers_remaining:0, networks_remaining:0, volumes_remaining:0, ep_removed:true, run_clean:true}. The recorded container was memeval-e80571b9-sut, with create/start/destroy timings of 109/93/160 ms.
  6. Reproducibility and comparison: with the same seed, five aggregate metrics matched the historical reference exactly. Retrieval sets matched in 73 of 75 cases; two differed at floating-point ties at rank 10. scripts/parity_diff.py <new> <ref> prints case-level differences.

Logs are in logs/0004-paeval_54558c1b…/(episode.json, sut.stderr.log, rpc-errors.jsonl ). Credentials are redacted, dataset text is not. This historical run predates data_flow. New reports disclose SUT and evaluator data flows separately; SUT network mode none alone cannot establish zero egress for the entire evaluation.

Container data flow

The evaluator runs on the host and external SUTs run in containers, connected by one protocol channel: the container main process's stdin/stdout. The evaluator uses docker start --attach --interactive to attach, writes one JSON-RPC 2.0 request per line, and reads responses from stdout. stderr is collected separately. The evaluator does not expose dataset files, a network listener, or a host socket through this protocol.

Outputs and evaluator handling

  • ingest → {batch_seq, accepted, filtered, failed}: counts must sum to the number of submitted events; otherwise IngestFailed.
  • retrieve → {items:[{id, text, source_ids[], score, timestamp}]}: retrieval scoring expands source_ids in return order, deduplicates first occurrences, and compares with gold. Nonempty references must identify ingested events in this episode and cannot repeat within an item. Unknown or future references are contract errors and must not be silently replaced with empty lists. Truly sourceless memories use source_ids: [] with their actual text; retrieval and fixed_reader/sources are recorded as unsupported. For LongMemEval, MemoryAgentBench, and BEAM, fixed_reader/items can answer from text, but retrieval metrics are unavailable for that case. Partial provenance must not masquerade as complete retrieval. Total returned text must not exceed max_context_chars; over-budget responses remain errors.
  • dump → {items:[{id, text, timestamp, layer}]}; IDs must be nonempty and unique.
  • Errors: JSON-RPC errors map to case error_type(rpc_error(<code>), rpc_timeout, frame_too_large, process_exited etc.); governor 503 responses with X-Memeval-Governor are forwarded by the bridge as gateway_exhausted / gateway_budget.
  • stderr is written to logs/<seq>-<ns>/sut.stderr.log (with credential redaction); RPC errors to rpc-errors.jsonl; sidecar output to sidecar-<name>.log.

SUT storage (vector databases, SQLite, graph files, model cache) resides in EP or /tmp and is removed with the episode; run --keep preserves EP for inspection. Outputs consist of protocol items and logs.

Adapter protocol v2 (paeval-v2)

The SUT process and evaluator communicate using JSON-RPC 2.0 over stdio, one JSON object per line and one request in flight. Responses require jsonrpc:"2.0", a matching numeric id, and exactly one of result and error. Defaults are a 16 MiB frame cap and 30 s request timeout, configurable through manifest adapter.max_frame_bytes, adapter.request_timeout_s. SUT stderr goes to episode logs with credential redaction only.

Method paramsresult
describe{} (separate process, ns=describe) {name, version, capabilities, limitations, read_only_queries, config}
reset{ns} (each reset uses a new process and episode directory) {}
ingest{ns, events:[PublicEvent]}{batch_seq, accepted, filtered, failed} (counts must sum to submitted events)
ready{ns, handle, deadline}{visible, stages[{name,status,warnings}], warnings}

Capabilities and errors

  • The runner gates behavior on capabilities: retrieve, typed_context, dump (memory_audit). Capabilities may be a string list or boolean map.
  • config.llm_notes[] is copied into report sut.llm.notes; HTTP bridges record the resolved host in config.bridge_base_url_host.
  • Errors map to case error_type: rpc_error(<code>) (bridges use -32000 for adapter exceptions), -32601 → UnsupportedCapability, rpc_timeout, frame_too_large, rpc_protocol_error, process_exited(<code>) (including OOM markers), ContractError, IngestFailed.

Three bridge types

Python bridge
adapter.kind: python-bridge. In the image: python -m memeval_bridge --adapter <module>:<Class> --config <json>; adapters inherit AdapterBase and implement describe/reset/ingest/ready/retrieve/answer/dump. Unimplemented methods return -32601. Validation checks event ID uniqueness, ingest counts, ready handles, and ingested-only retrieval references (otherwise rewritten to status:"unsupported").PYTHONPATH as {env}/bridge/python:{env}/project.
Node bridge
node bridge/node/index.mjs --adapter <file.mjs> --config <json>, exporting Adapter, with the same rules as the Python bridge.
HTTP bridge
adapter.kind: http-bridge: the project's server runs as a generic sidecar; the bridge forwards protocol operations to its HTTP API. bridge.base_url accepts only http://host:port (episode network alias or numeric address, without userinfo/path/query); bridge.routes files (version 1) declare path / method / body templates / item mapping / pagination per method; at most one headers_env is used as a Bearer token.
Native Go adapter
adapter.kind: native (currently octop ): evaluator Go code drives the in-container bridge over stdio.

All bridges redirect SDK stdout to stderr, reserving actual stdout for protocol frames.

Adding a system

  1. Write suts/<name>/manifest.json (v3): runtime, dependency locks, adapter.kind, process, sandbox.network, optional llm.env templates and sidecars[]; UPSTREAM.json recording project, repository, package, version, and license.
  2. Implement adapter methods for Python/Node: describe / reset / ingest / ready / retrieve (optional answer / dump ). The key requirement is to store event IDs with memories and return them during retrieval. HTTP server projects use routes.json; incompatible protocols use native adapters.
  3. env install builds the image and runs selftest; run --limit 3 checks three cases for scoring and valid references before a full run.
  4. Adapter describe().limitations and config.llm_notes must disclose unsupported behavior (such as ignored as_of or inexact top_k); these declarations enter the report.

Detailed checklist: suts/README.md.

LLM gateway

SUTs using gateway send model calls to a configured OpenAI-compatible endpoint, injected through manifest templates. open variants may declare direct services; call scope and metering depend on manifests and reports. Evaluator readers and judges are configured separately from SUT network modes:

MEMEVAL_SUT_LLM_API_KEY
Key; injected through a 0600 env.list and redacted from logs, reports, and argv
MEMEVAL_SUT_LLM_MODEL / …_REASONING_EFFORT
Default gpt-6-luna / low; run --sut-llm-model / --sut-llm-effort overrides it; manifest llm.model can pin it

In gateway mode, the framework rewrites {llm.base_url} to http://llm-gateway:<port>/…. One pure-Go HTTP governor per run ( __container-governor ) forwards only to the configured IP:port, attaches/detaches episode networks, and is destroyed with residue verification at run end. --sut-llm-concurrency (explicit total slots; otherwise per-episode fanout × --parallel, default fanout 8), --sut-llm-rpm (0 = unlimited), --sut-llm-budget-tokens (0 = unlimited), --sut-llm-max-pause (30m) govern queues, retries, circuit breaking, and budgets. Upstream 429/502/503/504/disconnections retry using Retry-After or exponential backoff, up to six retries. Five consecutive upstream failures open the breaker, starting at 60 s and doubling to 600 s. Exceeding max-pause or exhausting the budget returns 503 plus X-Memeval-Governor: exhausted|budget. SUT disconnections while queued or retrying do not count as upstream failures; they increment client_disconnects. A positive count means the client disconnected before completion; inspect queue delay, request deadlines, and logs for cause. governor/attempts.jsonl and billing.sut record usage for each upstream attempt ( calls counts attempts including retries). Missing usage is explicitly unmetered. Exhaustion preserves completed results and exits 4; use run --resume <out> --sut <manifest> to resume while retaining historical accounting. Embeddings may use image-local models or declared remote services; endpoint capability determines embeddings support. Direct embeddings need matching network configuration and disclosure. Report sut.llm{gateway_host, model, reasoning_effort, source, notes} records effective settings and SDK behavior, including reasoning_effort forwarding.

Three evaluation modes ( --mode)

Mode determines who answers and what is measured. The runner supports retrieval and fixed_reader; native_answer remains reserved. Retrieval uses information-retrieval metrics; answer scoring binds benchmark templates through protocols/<benchmark>.json. Alternative models, inputs, and implementation differences are disclosed in fidelity and deviations; a mode name alone does not establish official comparability.

MAB/BEAM join items in retrieval order under a Unicode-character budget including separators, dropping whole trailing items when necessary and disclosing truncation. No original text, gold, or future events are added. sources keeps its rules; items discloses input deviations and fidelity=partial. Unsupported benchmarks reject items before execution.
  • --reset-policy must be included in suite protocol.reset_policy_allowed; otherwise use protocol variant reset_policy_default.
  • --run-seed determines sampling and order and is recorded in reports. Use the reference seed for parity comparisons.
  • --parallel N (1..16, default 1) distributes runtime episodes among N workers. With fresh_per_case, each case is a runtime episode; with incremental_per_episode, an entire suite episode is one task. Workers have independent containers, EP directories, and logs. Incremental episode cases remain sequential; results assemble in suite order. Model randomness, load, and timeouts may change outputs, so stable order does not guarantee bitwise parity with serial execution. Gateway workers share one governor with per-episode fanout (manifest llm.concurrency, default 8) × N slots. Explicit --sut-llm-concurrency or corresponding environment/config values specify total slots directly. Too few slots can increase queueing; also check SUT request deadlines. Manifest sandbox.limits.cpus maps to --cpus; reports and stderr warn when N exceeds host CPU count.
  • --auto-resume-rate-limited N (default 0 = off): after a run, cases failing from governor exhaustion ( gateway_exhausted ) or rpc_timeout, plus unscheduled cases, wait for the suggested cooldown (30 s to --sut-llm-max-pause ), then --resume rerun in-process for up to N rounds, each recorded under resume_history[](auto: true, round, reason, waited_s, cases_retried, cases_recovered ). Budget exhaustion ( gateway_budget ) does not auto-resume; increase --sut-llm-budget-tokens and resume manually.
  • External SUT runtime lifecycle: reset (new container) → ingest batches → ready → retrieve → evaluator reader if required → destroy → residue check. Default fresh_per_case uses one runtime episode per case.
  • Evaluator models: --llm four modes and cassette directory ( MEMEVAL_CASSETTE_DIR ); each run writes llm_ledger.jsonl. Judging uses the Jev decision route ( jev-1.14.0 by default).

Reading scores

  • Every metric includes n: the cases for which it is defined. Memory-only hit/recall/mrr/ndcg/all_evidence averages only cases with gold (43 of 75 PMB retrieval cases); empty_result_correct averages only cases without gold covers the 32 negative cases, measuring restraint on irrelevant questions; precision averages only cases gold.exhaustive cases only.
  • The embedded Go glossary is authoritative for definitions, formulas, ranges, direction, aggregation, and caveats ( memeval results glossary ). Result-site and report ⓘ controls display the same text.
  • Comparability: deltas require matching dataset fingerprint, mode, top-k, reset policy, and protocol variant. Otherwise cards are shown side by side with differences identified. LongMemEval official recall_any@k and memory-only recall use different definitions and must not be pooled.
  • Read score and status together: scored excludes error / invalid / unsupported cases from the mean. A high conditional score with low coverage cannot establish overall quality.

<out>/logs/

  • Enabled by default; --no-logs disables logs. Each file is capped at 32 MiB ( --log-file-cap ); overflow retains the head and tail with an omission marker. Resumed episodes go into logs/resume-N/.
  • After each episode, enumeration by label=memeval.episode must find no containers/networks/volumes; otherwise the episode is Unenforceable and cannot score. Run completion repeats the check using label=memeval.run and writes residue.run_clean, also recording docker system df before and after.
  • Historical PMB-75 acceptance runs for echo, mem0, mastra, hindsight, cognee, and octop recorded zero residue. This is historical evidence, not a guarantee for future runs.
