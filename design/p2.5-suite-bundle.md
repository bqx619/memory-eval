# P2.5: Streaming suite bundle format

<!-- documentation-status: reference -->
> Technical reference. Historical milestones are not current operational instructions. See [current evaluation contracts](current-contracts.md); source types, schemas, and contract tests define implemented behavior.

Large monolithic suites motivated a container that supports streaming validation and random episode access. The recorded starting example was a 311 MB LongMemEval file requiring 14.3 seconds and 3.1 GB peak memory to validate. These are historical measurements, not portable performance guarantees. Existing single-file hashes remain unchanged.

## Files and canonical records

A bundle contains `suite.json`, `episodes.index.jsonl`, `episodes.jsonl`, and `import.json`. Each episode occupies exactly one canonical JSON line: sorted keys, compact UTF-8, no HTML escaping or trailing whitespace, and a final LF. Its object contains ID, cluster, events, and cases. Empty episode collections are invalid.

The index contains `{id,cluster_id,line,offset,bytes,sha256,events,cases}` in episode order. Line numbers are zero-based; offset is a byte offset; bytes and line hash exclude the LF. Counts and cluster ID must agree with the episode content.

The suite header retains semantic schema version 3.0 and existing metadata but omits the episodes array. It adds:

```json
{"container":{"format":"bundle","version":"1","episodes_file":"episodes.jsonl","index_file":"episodes.index.jsonl","index_sha256":"<sha256>","episodes":1,"events":1,"cases":1}}
```

## Root hash and trust

The bundle suite hash is SHA-256 of `CanonicalJSON(header) + "\n" + index_file_bytes`. The header includes the raw index hash, and each index row includes the episode-line hash. The header must not contain its own suite hash. Thus the root binds header, index, and every record without loading the complete history.

Internal consistency does not prove that a changed header is unauthorized: it merely yields a new root. `validate --expected-sha256` supplies an external trusted root. Registry suite hashes and prior reports provide such roots; registry checks use them for bundles. Line verification is on by default.

## Access and publication

`Open` accepts a legacy single file, bundle directory, or bundle header. `Container` returns single/bundle. `Iter` streams episodes; `Episode(id)` uses index offset/length with `ReadAt`; `Index` exposes metadata. Bundle `Suite.Episodes` is nil, so consumers use the access methods. A runner may cache one active episode, not the complete dataset.

The writer writes canonical episodes and accumulates the index, then publishes episodes, index, and finally the header by temporary-file rename. Validation checks canonical bytes, hashes, counts, IDs including cross-episode case uniqueness, semantics, and leakage. Single-file behavior is retained.

`memeval suite pack <single> --out <dir>` reports old/new hashes and warns that pairing/cassettes change. `suite index` reconstructs and checks an index. New importers default to bundle with `--format single` for small fixtures. Derived subsets copy selected records into self-contained bundles; shared parent references are not implied.

## Verification

Round-trip determinism, random access versus iteration, malformed canonical lines, line/index tampering, external-root header checks, pinned legacy hashes, schema generation, and independent root recomputation are the relevant checks. Historical performance targets were at most 5 seconds and 400 MB RSS for the LongMemEval bundle copy; report actual measurements and environment rather than treating targets as results. Packing must preserve per-case non-identity retrieval behavior under a controlled seed.
