> Technical reference. Historical milestones are not current operational instructions. See [current evaluation contracts](current-contracts.md); source types, schemas, and contract tests define implemented behavior.

This reference refines the dataset protocol while preserving existing v2 suites and reports. New runtime semantics were intentionally delivered in later milestones; successful schema validation alone does not mean a kind or ingestion mode can execute.

V2 keeps permissive decoding and existing semantics. V3 additions are optional on serialization, but placing a v3-only field in a v2 document produces `field X requires schema_version 3.0`. V3 strictly rejects unknown keys through nested suite, episode, event, case, gold, and substructure types.

## Fields and validation

Suite additions: `protocol_ref`, `license`, `data_nature`, `taxonomy{original_field,labels,canonical_map}`, `splits`, and named `SuiteProtocol`. Protocol additions include reset policies, time exposure/current-date policy, speaker mapping, text-only flag, haystack/filler/context ladder, and extended ingestion. Events add `turn_group`, modality, attachments, and tool role. Cases add query point, checkpoint, current-date override, and difficulty.

`end_of_history` requires cutoff equal to event count. `at_index` uses cutoff directly. `after_session_k` requires an existing checkpoint session and cutoff immediately after its last event. Splits reference existing cases and cannot overlap.

Gold retains v2 fields and adds polymorphic `evidence_refs`, abstention reference, MCQ spec, rubric, phrase set, sequence, summary reference, memory points, recommendation IDs, checker parameters, and disputed annotations. Flat and polymorphic evidence cannot coexist. Event/session references must resolve before cutoff; text/trajectory references contribute to `UnresolvedEvidenceRefs`.

Minimum gold rules: QA has answers or abstention; MCQ has options and a valid choice; retrieval has at least one non-nil evidence field (empty can be meaningful); typed context has expectations; rubric/phrase-set/memory-audit/recsys have their item lists; ordering has at least two sequence items; summary has a reference; agentic has a checker. Later HaluMem explicitly permits an empty audit checkpoint to update state without scoring.

`Upgrade` explicitly changes the schema version and then runs strict validation; it does not silently erase unknown fields. `memeval suite upgrade` reports old/new hashes and warns that old reports/cassettes are not pairable. Counts include `ByKind` and `UnresolvedEvidenceRefs`.

JSON schemas are generated from source types (draft 2020-12); `TestSchemasUpToDate` compares generated bytes with `schemas/suite.v3.json`, `benchmark-protocol.v1.json`, and `registry.v1.json`.

## Benchmark resolution and comparison

Protocol JSON is strict and contains protocol ID/version, upstream files, at least one variant, scoring, fidelity declarations, cluster basis, and overlaps. `Resolve` accepts `protocols/<id>.json#<variant>`, checks referenced template files and SHA-256, and returns the protocol file's raw-byte hash. Missing files, variants, or mismatched hashes are errors.

`result.Protocol.benchmark` records `{protocol_id,version,variant,ref,sha256,source}`. Binding precedence is suite then exact registry suite ID; absent binding emits `no benchmark protocol declaration bound`. Historical reports with a binding on only one side can compare when all prior compatibility checks pass, while recording `benchmark declaration present on one side only`. Two bindings differing in ID/version/variant/hash reject with `protocol differs: benchmark`; binding source is not a comparison dimension.

A template file hash differs from `params.template_set_sha256`. The original official model/template metadata remains provenance even when P5 uses a replacement decision judge with partial fidelity.

## Registry checks

An entry includes `id`, `name`, `repository`, `dataset_url`, `data_nature`, `task_kinds`, `protocol_id`, `variants`, `reported_scale`, license, pinned revision, implementation status, importer, lock path, suite references, overlaps, notes, and verification date. Suite references include suite ID/path/protocol and optional import statistics or trusted hash.

`registry check` verifies declared variants/protocols; required locks for imported/run entries; optional raw-file hash verification; suite existence, IDs, and consistent binding; symmetric overlap declarations; statistics versus validation counts; and a `scale:` explanation for mismatched published scale. Registered-only entries may warn about not-yet-created protocols. The historical manually transcribed PMB projection discloses its absent fetch lock rather than fabricating one. Output is `{ok,entries,problems}` with nonzero status on problems.

## Structural leakage checks

A deterministic public projection must contain no gold keys, including answer/label/correct/has_answer/expect/evidence/rubric/memory-points/choice/abstain names. Check original event attributes as well as serialized public DTOs. Public attribute keys must remain a subset of `AttributeNames`.

Validate anonymous identity fields against the expected mapping before scanning non-content values for original IDs. Natural role/owner words and short numeric IDs require field-level identity validation, not naive substring rejection inside arbitrary hashes. Original history content is exempt from original-ID substring scanning; answer-text scanning is `not_applicable`, because answers may legitimately occur in history. Text fields such as query and attributes are still checked for structural/identity leakage.

`validate` emits schema version, kind counts, unresolved evidence count, and `{problems,checked}` leakage status. Explicitly skipped leakage checks must be labeled `leak_scan:"skipped"`.

## Import statistics and verification

Shared statistics contain converter/input hash/schema, validated counts, kind/category/question-type distributions, time failures, skipped reasons/counts, upstream declared/observed scale and explanation, and limitations. `import.json` is canonical, deterministic, and reconciled against validation counts.

Conformance imports twice, compares canonical suite/statistics bytes with fixtures, validates, scans leakage, and reconciles counts. Existing normalized files are never rewritten to satisfy a test. The original gated-judge replay used as a compatibility check is historical: P5 removes those CLI flags. Current regression evidence must use supported contracts, and must distinguish an optional oracle skip from a passed check.
